02

Quality Check Point Cloud

Cek densitas, noise, dan duplikat sebelum diproses lebih lanjut.

Tahap krusial — data yang kotor akan menghasilkan tinggi pohon yang salah.

2.1 — Cek densitas & hitung resolusi CHM ideal

R CONSOLE
density <- rasterize_density(las, res = 1)
plot(density, col = height.colors(50))

avg_density <- mean(values(density), na.rm = TRUE)
avg_spacing <- 1 / sqrt(avg_density)
res_chm <- round(avg_spacing * 2, 2)

cat("Densitas:", round(avg_density,1), "titik/m2\n")
cat("Spacing:", round(avg_spacing,3), "meter\n")
cat("Resolusi CHM disarankan:", res_chm, "meter\n")
▲Kenapa bukan GSD foto langsung
Densitas dense cloud riil bisa jauh lebih rendah dari GSD foto tergantung tekstur permukaan & overlap. Aturan: resolusi raster ≥ 2x point spacing riil.

2.2 — Bersihkan noise & duplikat

R CONSOLE
las <- filter_duplicates(las)
las <- classify_noise(las, sor(k = 10, m = 3))
las <- filter_poi(las, Classification != LASNOISE)
03

Klasifikasi Ground

Klasifikasi dari nol dengan CSF — ekspektasi hasil lebih jarang.

Dense cloud fotogrametri belum pernah diklasifikasi — ini klasifikasi dari nol, hasilnya wajar jauh lebih jarang di bawah tajuk dibanding LiDAR.

R CONSOLE
las <- classify_ground(las, csf(
  cloth_resolution = 0.5,
  class_threshold = 0.3,
  rigidness = 2
))

table(las$Classification)
pct_ground <- sum(las$Classification == 2) / npoints(las) * 100
cat("Persentase ground:", round(pct_ground,1), "%\n")
▲Ekspektasi proporsi ground
Wajar berkisar 10–25% tergantung lebar gawangan terbuka. Jika < 5%, gawangan sudah tertutup — pertimbangkan DTM independen (Step 03B).

Visualisasi & cross-section check

R CONSOLE
plot(las, color = "Classification", size = 2, bg = "white")
R CONSOLE
p1 <- c(min(las$X), mean(las$Y)); p2 <- c(max(las$X), mean(las$Y))
las_tr <- clip_transect(las, p1, p2, width = 3)
ggplot(payload(las_tr), aes(X, Z, color = Classification)) +
  geom_point(size = 0.5) + coord_equal() + theme_minimal()
03B

Referensi Tanah Independen

Dua opsi: DTM sebelum tanam, atau titik GCP di area terbuka.

✕Rekomendasi terkuat
Jika Anda punya DTM dari survei sebelum tanam, LiDAR terpisah, ATAU titik GCP di area terbuka — gunakan salah satunya sebagai referensi tanah, BUKAN menurunkan ground dari dense cloud ini secara mandiri. Jauh lebih andal karena tidak bergantung pada gawangan terbuka yang mungkin sudah tertutup vegetasi saat akuisisi berjalan.

Opsi A — Point Cloud / DTM Sebelum Tanam

Paling ideal jika tersedia — merepresentasikan seluruh permukaan tanah, bukan hanya titik sampel.

R CONSOLE
dtm_external <- rast("data/DTM_sebelum_tanam.tif")
nlas <- normalize_height(las, dtm_external)

Opsi B — Titik GCP (Ground Control Point) sebagai Anchor

Jika tidak ada DTM sebelum tanam, tapi tersedia titik GCP (.shp) yang dipastikan berada di area terbuka di atas tanah — titik ini bisa dipakai dua cara berbeda, tergantung tujuannya.

B.1 — Validasi & koreksi bias DTM dari dense cloud

Bandingkan elevasi GCP aktual dengan nilai DTM hasil klasifikasi dense cloud di lokasi yang sama. Jika ada offset sistematis, koreksi seluruh DTM dengan nilai tersebut:

R CONSOLE
gcp <- st_read("data/titik_gcp.shp")
gcp <- st_transform(gcp, crs(dtm_dari_denseloud))

# Ekstrak nilai DTM tepat di lokasi tiap GCP
gcp$z_dtm <- terra::extract(dtm_dari_denseloud, vect(gcp))[,2]

# GCP harus punya kolom elevasi aktual, misal 'z_lapangan'
gcp$selisih <- gcp$z_dtm - gcp$z_lapangan

cat("Rata-rata bias DTM:", round(mean(gcp$selisih, na.rm=TRUE), 3), "m\n")
cat("SD bias:", round(sd(gcp$selisih, na.rm=TRUE), 3), "m\n")

# Jika bias konsisten (SD kecil), koreksi DTM dengan offset global
bias_koreksi <- mean(gcp$selisih, na.rm = TRUE)
dtm_terkoreksi <- dtm_dari_denseloud - bias_koreksi
▲Jika SD besar / bias tidak konsisten antar GCP
Bias yang bervariasi antar titik menandakan errornya bersifat lokal (bukan offset seragam) — koreksi global tidak tepat. Pertimbangkan opsi B.2 di bawah, atau kumpulkan lebih banyak titik GCP tersebar merata untuk interpolasi koreksi spasial.

B.2 — Jadikan GCP sebagai titik ground tambahan (paksa masuk klasifikasi)

GCP disuntikkan langsung ke point cloud sebagai titik ber-Class 2 (Ground) yang sudah pasti benar, memperkuat jaring triangulasi TIN terutama di sekitar lokasi GCP:

R CONSOLE
gcp <- st_read("data/titik_gcp.shp")
gcp <- st_transform(gcp, st_crs(las))
gcp_coords <- st_coordinates(gcp)

# Buat titik LAS baru dari GCP, paksa Classification = 2 (Ground)
gcp_las <- LAS(data.frame(
  X = gcp_coords[,1],
  Y = gcp_coords[,2],
  Z = gcp$z_lapangan,
  Classification = 2L
), header = las@header)

# Gabungkan ke point cloud utama sebelum normalisasi
las_gabungan <- rbind(las, gcp_las)
nlas <- normalize_height(las_gabungan, tin())
◆B.1 vs B.2 — kapan pakai yang mana
B.1 (koreksi offset) cocok jika jumlah GCP sedikit tapi tersebar merata, dan errornya diduga seragam di seluruh area. B.2 (suntik sebagai ground) lebih tepat jika GCP cukup banyak dan rapat, karena triangulasi TIN akan menganggapnya sebagai titik ground asli — perbaikan paling terasa di sekitar lokasi GCP itu sendiri, bukan area yang jauh darinya.

Jika tidak ada DTM sebelum tanam maupun titik GCP, lanjutkan ke Step 04 menggunakan ground point hasil klasifikasi dense cloud sendiri (Step 03).

04

Normalisasi Point Cloud (TIN)

Koreksi tinggi per titik langsung terhadap ground terdekat.

Tahap terpenting — setiap titik dikoreksi terhadap ground point terdekat langsung di point cloud, tanpa DTM raster yang rentan error interpolasi.

R CONSOLE
nlas <- normalize_height(las, tin())

gnd <- filter_ground(nlas)
summary(gnd$Z)
✓Kenapa TIN, bukan raster DTM
Triangulasi langsung antar ground point jauh lebih presisi dibanding kurangkan terhadap raster DTM yang sudah dibulatkan ke ukuran piksel.

Validasi — nilai Z ground harus ≈ 0

R CONSOLE
cat("Ground Z min:", min(gnd$Z), "\n")
cat("Ground Z max:", max(gnd$Z), "\n")
cat("Ground Z mean:", mean(gnd$Z), "\n")
R CONSOLE
nlas <- filter_poi(nlas, Z >= -0.1)
writeLAS(nlas, "output/normalized_pointcloud.laz")
05

Generate nCHM

Ubah point cloud ternormalisasi menjadi raster tinggi kanopi.

Karena point cloud sudah ternormalisasi, nilai Z tiap titik sudah langsung merepresentasikan tinggi di atas tanah.

R CONSOLE
chm <- rasterize_canopy(
  nlas, res = res_chm,
  algorithm = pitfree(
    thresholds = c(0, 2, 5, 10),
    max_edge = c(0, 1.5)
  )
)
plot(chm, col = height.colors(50))

na_pct <- sum(is.na(values(chm))) / length(values(chm)) * 100
cat("Piksel NA:", round(na_pct,1), "%\n")
▲Jika NA > 10%
Naikkan res_chm bertahap (0.1m → 0.15m) sampai NA di bawah 5-10%. NA berarti tidak ada dukungan titik sama sekali di lokasi tersebut.
R CONSOLE
writeRaster(chm, "output/nCHM_sawit.tif", overwrite = TRUE)
06

Zonal Statistics — Buffer 2m

Ekstrak tinggi di titik pokok ground-truth, dengan masking non-kanopi.

Karena Anda sudah punya titik pokok sawit sebagai ground-truth, posisi pohon sudah pasti benar — tinggal ambil statistik tinggi dari nCHM di sekitarnya.

R CONSOLE
titik_pokok <- st_read("data/titik_pokok_sawit.shp")
titik_pokok <- st_transform(titik_pokok, st_crs(chm))
buffer_pokok <- st_buffer(titik_pokok, dist = 2)
✕Masalah tersembunyi: piksel non-kanopi ikut terhitung
exact_extract mengecualikan NA, tapi nilai 0 BUKAN NA — piksel tanah/gawangan yang kebetulan masuk radius buffer 2m tetap dihitung sebagai data valid dan menarik rerata ke bawah. Untuk sawit muda bertajuk sempit, ini bisa signifikan: buffer 2m (diameter 4m) sering mencakup area di luar tajuk.

6.1 — Tentukan threshold kanopi & cek distribusi nilai

R CONSOLE
hist(values(chm), breaks = 50, main = 'Distribusi nilai nCHM')
# Cari lembah antara gerombolan nilai dekat 0 (tanah)
# dan gerombolan nilai tinggi tajuk sebenarnya

6.2 — Mask piksel di bawah threshold sebelum ekstraksi

R CONSOLE
threshold_kanopi <- 0.5  # meter — sesuaikan dgn tinggi sawit termuda

chm_masked <- chm
chm_masked[chm_masked < threshold_kanopi] <- NA

6.3 — Ekstrak statistik dari CHM yang sudah di-mask

R CONSOLE
stats <- exact_extract(
  chm_masked, buffer_pokok,
  fun = c("mean", "max", "min", "stdev", "count")
)

titik_pokok <- titik_pokok %>% bind_cols(stats) %>%
  rename(tinggi_rerata = mean, tinggi_maks = max,
         tinggi_min = min, tinggi_sd = stdev, n_piksel_kanopi = count)

6.4 — Tambahan: persentase tutupan kanopi dalam buffer

Metrik ekstra yang berguna untuk validasi silang — proporsi buffer yang benar-benar tajuk vs total area buffer, indikasi kepadatan/kesehatan kanopi:

R CONSOLE
stats_total  <- exact_extract(chm, buffer_pokok, fun = "count")
stats_kanopi <- exact_extract(chm_masked, buffer_pokok, fun = "count")

titik_pokok$pct_tutupan_kanopi <- round(stats_kanopi / stats_total * 100, 1)
◆Kenapa exactextractr
Menghitung fractional coverage — piksel yang sebagian masuk buffer tetap dihitung proporsional, bukan all-or-nothing. Penting karena buffer 2m hanya mencakup puluhan-ratusan piksel.
▲Cek n_piksel_kanopi sebelum percaya hasilnya
Nilai ini sekarang berarti jumlah piksel KANOPI saja (setelah masking), bukan total piksel buffer. Jika n_piksel_kanopi sangat rendah (<10) di suatu titik, rerata tinggi kurang andal — tandai untuk validasi lapangan prioritas. Kombinasikan dengan pct_tutupan_kanopi rendah sebagai indikasi tambahan pohon terhambat/tajuk jarang.
